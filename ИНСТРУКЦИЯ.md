# Лабораторная работа — Модель PaaS: Render вместо Heroku

Исходная методичка: создать приложение, развернуть на PaaS, изменить исходный код, развернуть повторно, продемонстрировать Git.

## 1. Вместо Debian: Windows + Git Bash + Docker Desktop

Распаковать архив так, чтобы файлы `app.py`, `Dockerfile`, `compose.yaml`, `requirements.txt` находились в **одной папке** (например `~/Desktop/Лабораторные работы/paas-lab`). Запустить Docker Desktop.

В Git Bash войти в папку с файлами и выполнить:

```bash
docker compose up --build -d
docker compose ps
curl http://localhost:8080
curl http://localhost:8080/health
```

Открыть страницу в браузере: http://localhost:8080

Должна отображаться **Версия 1.0**. URL `/health` вернёт `{"status":"ok","version":"1.0"}`.

Для остановки: `docker compose down`. Если порт 8080 занят, заменить только левое число в `compose.yaml`, например `8081:10000` и использовать localhost:8081.

## 2. Git: первый коммит

В Git Bash в папке проекта:

```bash
git init
git branch -M main
git add .
git commit -m "Initial Flask PaaS app v1"
git log --oneline
```

Если Git просит автора, задайте **свои** локальные имя и email:

```bash
git config user.name "Ваше имя"
git config user.email "ваш-email@example.com"
```

Затем повторите `git commit`.

## 3. GitHub: создать удалённый репозиторий

На https://github.com/new создать **пустой** репозиторий с именем `paas-heroku-lab`. Не добавлять README и .gitignore при создании, так как они уже есть локально (можно оставить репозиторий приватным, если Render подключён к GitHub и имеет доступ к нему).

В Git Bash выполнить (ЗАМЕНИТЬ `YOUR_GITHUB_LOGIN`):

```bash
git remote add origin https://github.com/YOUR_GITHUB_LOGIN/paas-heroku-lab.git
git push -u origin main
```

Если имя `origin` уже существует: `git remote -v` и при необходимости `git remote set-url origin <адрес>`.

Проверить, что `app.py`, `requirements.txt` и остальные файлы появились на GitHub.

## 4. Render: первый облачный деплой

1. Откройте https://dashboard.render.com/ и подключите свой GitHub-аккаунт.
2. Нажмите **New → Web Service**.
3. Выберите репозиторий `paas-heroku-lab`.
4. Выберите **Python 3** как Language/Runtime (не Docker для этого варианта).
5. Build Command: `pip install -r requirements.txt`
6. Start Command: `gunicorn --bind 0.0.0.0:$PORT app:app`
7. Instance Type: **Free**. Остальные настройки оставить по умолчанию.
8. Нажмите **Deploy Web Service**. После успешной сборки проверьте выданный адрес `https://...onrender.com/` и `/health`.

Если интерфейс предлагает создание Blueprint, файл `render.yaml` уже включает готовые параметры. Можно выбрать этот путь *вместо* ручного создания Web Service, но не создавать два сервиса одновременно.

Бесплатный Render засыпает после 15 минут простоя; первый запрос после этого может выполняться заметно дольше. Сайт использует непостоянную файловую систему — для этой лабораторной это не мешает.

## 5. Изменить код, сделать второй коммит и повторно деплоить

Открыть `app.py` в Блокноте:

```bash
notepad app.py
```

Заменить **только** строку:

```python
APP_VERSION = "1.0"
```

на:

```python
APP_VERSION = "2.0"
```

Сохранить. В Git Bash:

```bash
git add app.py
git commit -m "Update PaaS app to version 2"
git push
```

В Render включённый Auto Deploy автоматически запустит новую сборку. Открыть ту же облачную ссылку: должна отображаться **Версия 2.0**. `/health` должен показывать `"version":"2.0"`.

Локальный контейнер продолжит отображать старую версию, пока не выполнить `docker compose up --build -d` заново — это ожидаемо.

## 6. Что показать преподавателю

- Локальный браузер `http://localhost:8080` и терминал `docker compose ps` (альтернатива Debian).
- Историю Git: `git log --oneline` (два коммита).
- GitHub-репозиторий с исходным кодом.
- Облачный адрес Render с **Версией 2.0** и вкладку Render Deploys с первой и второй сборкой.
- Сравнение: локальный Docker — среда тестирования, Render — PaaS: сервис сам устанавливает зависимости, развёртывает приложение и выдаёт публичный адрес.
