# Лабораторная работа: модель обслуживания PaaS (Render вместо Heroku)

## Цель работы
Познакомиться с PaaS и Git, разработать тестовое Python-веб-приложение, выполнить первичное развертывание и повторный деплой после изменения программы.

## Используемое программное обеспечение
Windows, Git Bash, Docker Desktop, Python 3.12, Flask, Gunicorn, Git, GitHub, Render (бесплатный Web Service).

## Обоснование замены инструментов
Методичка допускает использование Debian в виртуальной машине в качестве рабочей среды, но не требует конкретной ОС. Для локальной разработки выбран Windows с Docker Desktop и Git Bash: Docker предоставляет изолированное окружение приложения без ручной настройки Debian. В качестве PaaS вместо Heroku выбран Render, который поддерживает Python и автоматический деплой из GitHub.

## Ход работы

### 1. Подготовка приложения
Созданы `app.py`, `requirements.txt`, `Dockerfile`, `compose.yaml`, `render.yaml`, `Procfile`, `.gitignore`. Python/Flask обрабатывает запросы `GET /` и `GET /health`. Первоначальная версия — 1.0.

**Доказательства:** скриншот файлов проекта и вывода `cat app.py` / `ls`.

### 2. Локальное тестирование
Запуск: `docker compose up --build -d`. Проверка: `curl http://localhost:8080` и `curl http://localhost:8080/health`. В браузере отображается версия 1.0.

**Доказательства:** скриншоты `docker compose ps`, браузера с версией 1.0.

### 3. Первый коммит и публикация в GitHub
Выполнены `git init`, `git add .`, `git commit -m "Initial Flask PaaS app v1"`, `git push -u origin main`.

**Доказательства:** скриншоты репозитория GitHub и `git log --oneline`.

Создан Render Web Service на бесплатном тарифе с подключенным GitHub-репозиторием. Команда сборки: `pip install -r requirements.txt`. Команда запуска: `gunicorn --bind 0.0.0.0:$PORT app:app`. Получен публичный HTTPS-адрес.

Подготовлен локально запускаемый Docker-проект и Git-репозиторий с историей изменений. После публикации в Render проверяется работоспособность PaaS: облачная платформа автоматически собирает, запускает и обновляет приложение по изменениям в GitHub.

## Ответы на контрольные вопросы

**1. Почему Agile становится популярнее?**
Agile позволяет разрабатывать ПО короткими итерациями, регулярно показывать работающий результат, получать обратную связь и быстрее учитывать новые требования. В каскадной модели изменения после завершения этапа обычно обходятся дороже.

**2. Чем PaaS удобнее IaaS для публикации приложения?**
При IaaS обычно нужно самостоятельно настраивать виртуальную машину, ОС, веб-сервер, обновления и многое другое. PaaS предоставляет готовую среду выполнения и инструменты публикации: разработчик в основном отвечает за код и настройки приложения. Компромисс — меньше контроля над инфраструктурой.

**3. Для чего нужны `git add`, `git commit`, `git push`?**
`git add` помещает выбранные изменения в индекс; `git commit` сохраняет их как новый коммит в локальной истории Git; `git push` отправляет локальные коммиты в удалённый репозиторий GitHub.

**4. Каковы преимущества Heroku/Render относительно локального окружения?**
Публичный HTTPS-адрес, доступность приложения извне, автоматизированный деплой из Git, управление средой и зависимостями на стороне платформы. На бесплатном тарифе Render есть ограничения, например остановка сервиса после простоя.
